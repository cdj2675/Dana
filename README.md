# Dana

현재 버전: **1.20.1** (화면 왼쪽 위 이름 옆에 표시)

저녁 있는 삶을 위한 디자인 검수 자동화

맨 위 탭이 두 개입니다.

- **검수** — 디자인(PDF·SVG·PNG·JPG)을 기준 원문·디자인 시스템과 맞춰 검수하고, 결과를 적용해 PPTX·SVG·PNG·JPG로 추출합니다. 처음 열면 이 탭이 보입니다.
- **디자인(beta)** — 과업지시서·원고·디자인 자료를 올리면 질문 몇 개와 확정 버튼 세 번으로 원고 쪽수만큼의 제안서 초안(PPTX)을 만듭니다.

두 탭은 한 프로젝트를 같이 씁니다. 디자인 탭에서 만든 쪽·디자인 시스템·원고가 그대로 검수 탭의 입력이 됩니다.

## 디자인 탭

전략 문서 「Dana 디자인 모드 전략」(2026-11-03)을 따릅니다.

화면은 4단계입니다. 1~3단계는 각각 확정 버튼 하나로 끝나고, 4단계에서 만들고 내보냅니다.

| 단계 | 안의 화면 | 사용자가 하는 일 | 확정하면 |
|---|---|---|---|
| ① 자료·스타일 | 자료 올리기 → 디자인 시스템 | 세 칸에 파일 끌어다 놓기(과업지시서 칸에는 제안요청서·입찰 공고도 함께), 색·글꼴·치수·그리드·아이콘 확인, 기본 팔레트 고르기(색 1~2개 조정) 또는 내 디자인 시스템 넣기 | 디자인 가이드 v1.0 (`.md` + `tokens.json`) |
| ② 쪽 계획 | 한 화면 | 이상이 없으면 바로 확정. 배점 연결·보완 제안은 접혀 있고, 인포그래픽 유형은 「바꾸기」를 눌렀을 때만 고름 | 페이지 플랜 |
| ③ 시안 고르기 | 한 화면 | 같은 샘플 3쪽을 세 시안(정돈형·구조형·강조형)으로 보고 하나 고르기(정돈형이 미리 골라져 있음) | 스타일 + 인포그래픽 배치(가이드 v1.1) |
| ④ 전체 생성 | 한 화면 | 보드에서 고칠 쪽만 눌러 프리셋으로 고치기, 맨 아래에서 형식 골라 내보내기(내보내기 전 점검이 자동으로 돎) | PPTX·PDF·PNG/JPG·SVG·엑셀 |

완성도 기준(최소선, 1.8.0) — 실제 제출본 2종(엘앤케이비즈 76쪽·금성환경 56쪽, 표지·목차 제외)에서 잰 값을 기준으로 삼되, 색·모양은 복제하지 않고 Dana 고유 스타일로 그립니다.

| 기준 | 제출본 측정값 | Dana 최소선 | 못 맞추면 |
|---|---|---|---|
| 평가 항목 표시 | 모든 쪽 | 머리틀에 번호·이름·배점 | 배점 연결에서 절을 이으라는 안내 |
| 헤드 메시지 | 엘앤케이비즈 모든 쪽 | 쪽마다 1개 | 원고 첫 줄에 넣으라는 안내 |
| 표·도식·사진 | 없는 쪽 0 | 쪽마다 1개 이상(불릿만 있으면 도식 후보로 바꿈) | 원고에 단계·「이름 : 설명」·표를 넣으라는 안내 |
| 본문 세로 채움 | 10분위 74%·99% | 70% 이상(모자라면 여유 배치를 자동 적용) | 원고 보강 안내 |
| 본문 글자 크기 단계 | 3단계 | 4단계 이하 | — |
| 쪽당 원고 글자 | 10분위 580자 | 400자(참고) | 원고 보강 후보 |
| 넘침·글자 하한 | — | 0건 | 원고 분량 줄이기 |

4단계 「전체 생성」 위에 「완성도 기준」이 쪽 수로 나오고, 쪽마다 통과·미달 항목과 고칠 방법이 나옵니다. 미달 필수 항목은 내보내기 전 점검에 「확인」으로 올라갑니다.

쪽 틀: 머리틀(평가 줄 → 절 제목 → 배점 비중 막대) → 헤드 메시지 → 소제목별 본문·도식 → 사진 → 핵심 실행 사항 → 자료 출처 → 쪽 번호. 무드별 머리틀은 옅은 바탕(네이비)·흰 바탕(그린)·무채색(모노). 글자: 본문 11pt·줄 간격 1.6, 표 10.5pt, 소제목 13.5pt, 헤드 메시지 14.5pt, 절 제목 18pt. 상자는 내용 크기대로 두고 늘리지 않습니다.

규칙

- **과업지시서가 최상위**: 글자 크기·쪽수·블라인드 같은 제한 조항은 화면 위 배너에 잠금으로 고정되고, 디자인 시스템의 하한·상한이 됩니다. 애매한 조항은 「확인 필요」로 올라와 사용자가 확정합니다.
- **원고 불변**: 원고 1쪽 = 디자인 1쪽. 원고에 없는 문장·수치는 만들지 않고, 줄바꿈·불릿 나누기만 자동으로 합니다. 보완 제안(부족·과잉·분량 조정)은 원고 담당자에게 전달할 목록으로만 남깁니다. 도식으로 만들 수 있는 곳은 묻지 않고 Dana가 바로 도식으로 만듭니다.
- **과업지시서 + 제안요청서를 함께**: 과업지시서 칸에 여러 문서를 함께(또는 차례로) 올리면 같이 읽습니다. 배점표는 배점이 있는 문서(보통 제안요청서)에서 가져오고, 제약 조항은 모든 문서에서 모아 같은 종류는 가장 엄격한 값으로 합칩니다. 과업지시서의 과업 내용은 배점 항목에 붙여 원고 절 연결에 씁니다. 문서마다 따로 뺄 수 있고, 확정·해당 없음으로 바꾼 조항은 문서를 더하거나 빼도 유지됩니다.
- **배점이 없으면 요구사항으로 중요도**: 배점표가 있으면 그대로 따릅니다. 없으면 ① 배점 없는 평가 항목(평가 요소·지표) 표·목록, ② 「과업 내용·요구사항·수행 내용」 아래 과업별 소제목 순으로 찾아 항목을 만들고, 문서 근거(반드시·필수·중점·특히 같은 강조, 요구 문장 수, 다른 곳 반복 언급, 평가 방법의 중점 언급)로 중요도 상·중·하(1~5)를 매겨 비중 %로 씁니다. Claude를 쓸 수 있으면 Claude가 같은 기준으로 묶고 매기며, 문서에 없는 배점 숫자는 받아들이지 않습니다. 사용자는 1단계에서 상·중·하를 바꾸거나 항목을 뺄 수 있습니다.
- **배점은 밀도**: 배점(또는 중요도) ÷ 쪽수로 도식 밀도와 샘플 순서를 정합니다. 쪽마다 큰 도식은 1개, 같은 패턴이 3쪽 연속이면 두 번째 후보로 바꿉니다.
- **인포그래픽 패턴 10종**: 불릿, 카드(2·3열+아이콘), 표, 라벨 표, KPI 타일, 흐름, 순환(되돌이표), 허브, 타임라인, VS 대비 + 사진 프레임·리드 박스·결론 배너.
- **글자 맞춤**: 올린 TTF·OTF로 폭을 재서 어절 단위로 줄을 나누고, 남는 높이를 간격·카드·표 행에 나눠 본문 끝선까지 채웁니다. 넘치면 간격 → 아이콘·여백 → 큰 도식 → 줄 간격 순으로 줄입니다.
- **편집 가능한 PPTX**: 글상자·기본 도형(쉐브론·둥근 사각형 등)·표로 만들고, 한글 서체 속성(동양어 문자 집합·panose)을 채워 다른 PC에서도 줄바꿈이 같게 합니다.
- **출력 전 검수**: 내보내기를 누르면 검수 탭이 먼저 돌고, 오류 0 또는 「확인함」 처리 뒤에 내보냅니다. 과업지시서 위반은 확인 처리로 넘길 수 없습니다.

레퍼런스 성향(1.10.0): 디자인 자료의 레퍼런스(이미지·여러 쪽 PDF)에서 모양은 따라 하지 않고 쪽 밀도(본문 사용률)·색 면적·자주 쓰는 구성(표·카드·단계·수치·일정·사진·아이콘, Claude가 읽음)만 읽어 묶음 간격·옅은 바탕 사용·도식 유형 우선순위·아이콘 사용에 반영합니다. 2단계에서 결과를 보고 「배치에 반영」을 끌 수 있습니다.

아직 하지 않은 것: 원고 요약 승인(노란 점), 글자 단위 프리셋(키우기·강조·한 줄로), 벡터 PDF(지금은 250dpi 이미지 PDF).

## 검수 탭

`디자인(필수)` + `디자인 시스템` 또는 `기준 원문` 중 하나 이상

| 올린 자료 | 하는 검사 |
|---|---|
| 디자인 + 디자인 시스템 | 디자인 시스템 규칙(여백·헤더·쪽 번호·글자 크기·글꼴·색·그림자 등), 오탈자 후보, 표기 통일, 아이콘 대장 |
| 디자인 + 기준 원문 | 원문 대조(누락·글자 다름·원문에 없음), 수치·조항, 오탈자 후보, 표기 통일 |
| 셋 다 | 모든 검사 |

1. **자료 올리기** — 디자인 / 디자인 시스템(MD·PDF·PPTX·DOCX·HWP·HWPX·JSON·이미지) / 기준 원문(PPTX·DOCX·HWP·HWPX·PDF·TXT)
2. **검수** — 쪽별 결과, 항목별 목록, 엑셀 내려받기
3. **결과 적용** — 쪽 범위와 항목을 골라 SVG에 반영(PDF·이미지는 수정 목록)
4. **추출** — PPTX·SVG·PNG·JPG

## 실행 환경

claude.ai 아티팩트로 게시해 쓰도록 만들었습니다. 아래 기능은 claude.ai 안에서만 동작합니다.

- 작업 공간 저장(내 공간·파티): `window.claude.use('db')`, `use('user')` — 디자인 탭의 확정 상태(가이드·매핑·플랜·스타일)도 여기에 저장
- 올린 파일 보관: `use('assets')` (편집 권한이 있을 때만)
- Claude로 읽기: `use('sample')` — 디자인 시스템 문서·이미지 글자, 과업지시서 조항·배점, 평가 항목 ↔ 원고 절 연결
- 파일 내려받기: `use('downloads')`

일반 웹 서버에서 열면 업로드·검수·디자인 생성은 되지만 저장과 Claude 읽기는 꺼집니다(과업지시서·연결은 문서에서 직접 찾는 방식으로 대신함). 내려받기는 브라우저 기본 방식으로 동작합니다.

## 자료 보관

- **올린 파일 보관(기본 켜짐)**: 원고·디자인 자료(그리드·폰트·레퍼런스)와 검수 탭의 디자인·기준 원문 파일을 아티팩트 파일 보관함에 넣어, 같은 계정이면 다른 컴퓨터에서 열어도 다시 올리지 않고 이어집니다.
  - 파일은 AES-GCM으로 잠근 뒤 넣습니다. 내 공간은 사람마다 따로 만든 열쇠(본인만 읽는 칸에 보관), 파티는 파티 코드 열쇠를 씁니다.
  - 보관함은 한 조각에 20MB까지라, 큰 파일은 12MB씩 나눠 넣고 열 때 다시 붙입니다. 전체 한도는 아티팩트 보관함 용량이며 작업 공간 메뉴에 사용량이 나옵니다.
  - 각 탭 「자료 올리기」 오른쪽 위 「자료 초기화」: 디자인 탭은 올린 자료·고른 무드와 색·확정 단계·보관 파일·저장된 진행 상태를 모두 지우고, 검수 탭은 디자인 파일·기준 원문(보관 파일 포함)을 지웁니다. 검수 탭의 디자인 시스템 설정과 저장된 적용본은 남습니다. 누르면 한 번 더 확인합니다.
  - 작업 공간 메뉴(오른쪽 위)에서 보관을 끄거나 보관 파일을 지울 수 있습니다. 끄면 1.1 이전처럼 화면에만 남습니다.
  - 보관은 이 Dana의 **편집 권한**이 있어야 합니다. 댓글 작성자·보기 전용은 지금처럼 다시 올려야 합니다.
  - 과업지시서 파일은 보관하지 않습니다. 읽어 낸 평가 항목·제약 조항은 디자인 탭 확정 상태와 함께 저장됩니다.
- 디자인 시스템·허용 목록·용어집·기준 수치·적용 결과·디자인 탭 확정 상태는 작업 공간에 저장합니다.
  - 내 공간: 본인만 읽음
  - 파티: 16자리 파티 코드로 AES-GCM 암호화, 코드를 아는 사람만 읽음

## 학습 — 먹이로 자라는 Dana

오른쪽 위 고양이를 누르면 「학습」 화면이 열립니다. 팀원이 완성 제안서나 디자인적으로 잘 만든 페이지를 먹이로 주면 경험치가 오르고, 경험치와 먹이 수가 차면 레벨업 대기가 됩니다. 전체 설계는 「Dana 성장 전략」 문서에 있습니다.

- **먹이 종류**: 완성 제안서 PDF, 디자인 페이지(PDF·PNG·JPG). 문서 종류가 「자동」이면 이미지와 5쪽 이하 PDF는 디자인 페이지, 나머지는 제안서로 봅니다.
- **픽셀·글자 소화**(브라우저): 본문 밀도·색 면적·본문 채움·위아래 무게·쪽당 글자 수·글자 크기(본문·큰 글자·단계 수). 제안서는 앞 3쪽·뒤표지·간지를 빼고 최대 80쪽, 디자인 페이지는 모든 쪽(최대 30쪽).
- **디자인 완성도 소화**(Claude): 쪽을 4장씩 모은 이미지를 보고 정해진 목록·점수로만 답합니다. 디자인 페이지는 최대 12쪽(3번 호출), 제안서는 본문 4쪽(1번 호출).
  - 도식: 단계·순환·위계·매트릭스·일정·큰 숫자·비교·카드·표·그래프·배치도·아이콘·사진
  - 내용→도식 짝: 절차·비교·조직·성과·일정·구성요소·위치·현황·목표·전략 → 도식
  - 세련됨(1~5): 정보 위계·정렬·여백·색 절제·글자 다듬기 / 표현력(1~5): 그림으로 바꾸기·핵심 강조·수치 시각화
  - 표현 기법(목록 15개 중): 번호배지·큰숫자강조·아이콘카드·강조바·요약상자 등
- **저장**: 공용 저장소 `grow_feeds/<파일 지문>`에 숫자와 목록 이름만 넣습니다. 원본·파일 이름·문서 문장·색 값은 저장하지 않습니다. 같은 파일은 지문으로 한 번만 셉니다.
- **경험치**
  - 제안서 등: 본문 1쪽당 1(최대 60) × 결과(수주 ×2, 고득점=만점의 90% 이상 ×1.5, 탈락 ×0.5, 모름 ×1) × 제안서가 아니면 ×0.5
  - 디자인 페이지: 1쪽당 3(파일당 최대 30) × 완성도(세련됨 60%·표현력 40%) 4 이상이면 1.5. 결과·점수는 쓰지 않음
  - 새 분야면 +20%
- **확인 필요(회색 경험치)**: 본문 10쪽 미만·글자를 읽을 수 없음·다른 먹이와 동떨어진 수치(제안서), 완성도 2.5 미만·Claude 분석 없음(디자인 페이지). 승인자가 통과시켜야 채워집니다.
- **레벨업 대기**: 경험치(Lv1→2 100, →3 250, →4 450 …) + 이번 레벨 먹이 3개 이상.
- **레벨업 검토(승인자 = 이 Dana의 소유자)**: 학습 화면 「레벨업 검토 열기」 → 먹이마다 포함·제외(확인 필요 먹이는 체크하면 통과) → 「레벨업하면 이렇게 바뀌어요」 전후 표 → 디자인 탭에 원고가 있으면 앞 2쪽을 두 레벨로 그린 전후 비교 → 「레벨업 확정」. 넘친 경험치는 다음 레벨로 넘어가고, 제외한 먹이는 다시 쓰지 않습니다.
- **공용 체질**(`grow_meta/state`): 포함한 먹이로 다시 계산한 기본값. 한 번에 남은 차이의 30%까지만, 안전 범위 안에서만 움직이고 한 문서 비중은 30%를 넘지 않습니다.
  - 제안서 먹이 → 본문 채움 기준(하위 10%×0.95, 60~85%), 쪽당 글자 기준(하위 10%×0.9, 250~600자), 본문 밀도(15~40% → 묶음 간격), 색 면적(3~15% → 옅은 바탕 사용)
  - 디자인 완성도 → 도식 점수(쪽당 도식 빈도 → 0~3, 패턴 점수 ±9), 인포그래픽 적극성(표현력 → 개조식 목록 외 패턴 ±6). 세련됨·표현력 평균은 참고값으로 기록
  - 프로젝트에 레퍼런스를 넣으면 그 성향이 먼저입니다(공용 체질 → 레퍼런스 순으로 덮어씀).
- **진행 중인 작업 보호**: 디자인 가이드를 확정할 때의 레벨을 프로젝트에 고정합니다. 그 뒤 Dana가 자라면 디자인 탭에 「새 레벨 기준으로 다시 만들기」가 뜹니다.
- **되돌리기**: 승인자는 레벨 기록에서 마지막 레벨을 되돌릴 수 있습니다. 체질이 이전 값으로 돌아가고 그 레벨의 먹이는 다시 검토 대기가 됩니다.
- **고양이 상태**: 먹는 중 > 배부름(레벨업 대기) > 배고픔(7일 넘게 먹이 없음) > 보통. 모든 레벨에서 같은 모습입니다.
- 먹이는 저장소에 쓸 권한(편집자·같은 조직 참여자)이 있어야 줄 수 있습니다.
